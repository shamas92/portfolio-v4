# Design — Annotated Proof

Replaces the v4 "specimen cabinet" (drawers, trays, walnut, brass).
The site reads as a clean technical document: claims are highlighted,
and each opens its evidence in a margin note. The concept shows
through behavior; nothing on the page explains it.

## Tokens

CSS variables in `src/app/globals.css`. Two layers: raw values in one
block, semantic aliases below. Components use only the aliases.

| Role | Light | Dark (`prefers-color-scheme`) |
| --- | --- | --- |
| paper | #F4F6F5 | #14191B |
| ink | #232A2E | #E4E9EA |
| margin (secondary text) | #5B666B | #9AA6AA |
| verified-wash (claim highlight) | #CDE8D9 | #1F4034 |
| verified-ink (links, focus ring, check) | #0E6B49 | #6FD1A4 |

Green appears only where it means "verified". No gradients, no
decorative shadows, no identical rounded-card kit. Hairline rules
(`--rule`) separate rows and sections.

## Type

- Schibsted Grotesk (name, headings, UI) and Source Serif 4
  (case-study prose, line-height 1.6, measure under 75ch), loaded with
  `next/font`, self-hosted and subsetted (latin + latin-ext, so
  ä ö ü ß render), with size-adjusted fallbacks.
- Monospace only for real code or hashes. The site has none, so no
  monospace face ships.
- No tracked all-caps eyebrow labels above headings, no middle-dot
  meta strings, no single accented word in a headline, no numbered
  markers on non-sequential content, no arrows appended to links.

## Layout

Left-aligned. One reading column plus a margin column on desktop:
the page grid is `240px | 1fr | 240px`; sections and annotated rows
are subgrids, so proof notes land in the margin track. On mobile the
note becomes an inline disclosure under the claim.

Sections (one instance of each): Hero, Work, Stack, Background
(a real timeline), Contact (in the footer). Work is five ruled rows
with one pattern: name, year, one-sentence outcome, one proof
statement, stack. Each row links to `/work/[slug]`, generated with
`generateStaticParams`. Each case study has the same four blocks:
Problem, Architecture, Outcome, Proof.

## Motion

One orchestrated moment only: the wash under "prove every claim"
sweeps in once on load (`transform: scaleX`, 600 ms, ease-out).
Disclosures fade 200 ms (opacity + a 2 px shift). Row hover/focus
shows a thin indicator via `transform: scaleY`. Only transform and
opacity animate. `prefers-reduced-motion` shows final states, no sweep.

## Interaction

Proof notes are disclosure buttons (`aria-expanded`, `aria-controls`).
They open on click, tap or Enter, close on Escape, and never depend
on hover. Closing returns focus to the trigger. Touch targets are at
least 44 px. Buttons use plain verbs ("See projects", "Copy email").

## Content

One typed module, `src/content.ts`: profile, projects, background,
skills, and the `contentTodos` list. Missing facts render a visible
`TODO(content)` marker in development and are omitted in production.
Nothing is invented; the LeaseLens IoU figure is demoted to supporting
evidence and "registered IoU" is explained in plain words.

## Components

`ProofNote` (claim button + margin note + annotated paragraph),
`ProjectRow`, `CaseStudy`, `Timeline`, `StackGroup`, `SiteHeader`,
`SiteFooter`, `CopyEmailButton`, `Todo`. Server components by
default; client components only for disclosures and the copy button.

## SEO

Per-page title/description, canonical URLs, Open Graph + Twitter
images (`public/og.png`, 1200×630, regenerated by
`scripts/make-og-image.py`), sitemap, robots, `<html lang="en">`,
JSON-LD Person.
